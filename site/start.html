SchemaForge

An open-source schema design and management tool where you and your coding agent work on the same live design.

It is built on two full-feature engines, MySQL and PostgreSQL, and every managed service or compatible database (RDS, Cloud SQL, Aurora, Percona, AlloyDB, TiDB, Spanner, CockroachDB) is a subset that falls into one of them.

Everything it knows of a design is rows of one PostgreSQL 18 database, kept consistent by the database itself.

Where it stands

4 of 11 objectives done.

The product is being rebuilt from its spec, one objective at a time, each its own issue and pull request. What is built today is the store: the cortex every engine shares, and engine_mysql, proven by round-tripping every object of MySQL 5.7 to 9.7 and Percona Server through it on every pull request; and the app's store and core in Rust (turns, undo, restore, the bell, schema-forge check), proven against a real store on every pull request. The rest of the app comes next (the engine interface, the server with the agent's MCP, the canvas), a complete product on its first engine; then engine_postgresql and its family, each a plugin the app takes as it is.

Try it

Install the store and run its proofs.

You need PostgreSQL 18 (with its psql and pg_dump) and a superuser on it, Python 3.12 or later, and Docker for the proofs.

git clone https://github.com/k8nstantin/schema-forge && cd schema-forge
python3 tools/local/install.py --user <your superuser> --fresh   # the database, every schema and service account; locked in
python3 tools/mysql/all.py                                          # engine_mysql proven on every MySQL and Percona server

The installer asks for your password, and for drop before replacing an earlier install. It writes each service account's password only to its accounts file, then checks that what it installed is exactly the database CI tested.
