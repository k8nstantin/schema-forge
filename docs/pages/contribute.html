Contribute with your coding agent

Point your agent here. It will read the whole spec.

SchemaForge is designed in the open and written down before it is built: the database, the rules, every task. Most people contribute through a coding agent now, so the project hands your agent one brief that lists everything it needs, in the order to read it.

The brief for agents llms.txt Ask a question

The prompt

Paste this into your agent.

Read https://k8nstantin.github.io/schema-forge/agents.md and every file it lists, in its order. Then tell me, in your own words, what SchemaForge is, how it is built, and which open task or issue you think fits me; don't change anything yet.

Your agent reads agents.md, follows its links to the raw files on GitHub, and comes back with what it understood. Nothing changes until you decide what to do.

How it goes

Four steps, you in charge of each.

Step 1

Point your agent at the brief

Paste the prompt above into Claude Code, Codex, Cursor or any agent that can read the web. It reads agents.md and every file it lists, in order: the root, the rules, the files that decide, every task.

Step 2

Let it explain the project back

Before anything changes, your agent tells you what it understood: what SchemaForge is, how it is built, which decisions are still open, and what could fit you.

Step 3

Pick something together

A good first issue, a sample of real DDL that breaks a reader, an engine for a database you know, or a question in Discussions. Larger work is agreed with the maintainer first, often as a task file.

Step 4

Build it the way the project does

One issue, one branch, one pull request; tools/check.sh passes first; your name on the commits, no attribution. Your agent follows the rules the brief lists, and you answer for every line.

What your agent reads

The whole spec, in the order that makes sense of it.

The root first (who decides what, how every task is built, every decision with its date), then the rules, the files that decide, the task files in build order, and the design docs. The brief is generated from the repository on every build, so it never falls behind.
